# 自适应精简决策架构设计

## 目标

在保留现有经典多智能体 Graph 和快速单模型模式的同时，新增默认的自适应精简架构。普通交易日不调用 LLM，一般变化只调用一次，重大变化使用两步投资委员会，将完整复核的常见调用数从 12～16 次降至 2 次。

## 会话架构模式

新增会话字段 `decision_architecture`，允许以下值：

- `adaptive`：默认。零调用监控、一次快速决策、两次委员会复核。
- `classic_graph`：保留现有 Hybrid/Graph 多智能体流水线。
- `fast`：保留现有单模型 DecisionAgent。

保留 `use_full_graph` 字段用于读取旧数据，但新代码以 `decision_architecture` 为准。数据库迁移时，旧会话的 `use_full_graph=1` 映射为 `classic_graph`，其余映射为 `fast`；新会话默认使用 `adaptive`。

## 自适应调度

`AdaptiveDecisionAgent` 读取现有 `DailyContext`，复用新闻差异、价格区间、技术恶化/改善和连续维持判断等检测逻辑。

### 零调用路径

存在有效的上一决策，且没有重大消息、技术状态切换、价格离开决策区间或定期复核要求时，沿用原有观点和区间，不调用 LLM。

### 快速路径

一般新信息、有效期届满后需要轻量复核，或变化不足以启动委员会时，调用一次低思考档位模型，直接返回结构化 `Decision`。该路径必须看到真实账户状态、最新指标、新增消息、历史观点和已注入经验。

### 委员会路径

以下情况触发两步委员会：

- 会话首个决策日，尚无有效观点；
- 命中重大消息规则；
- 技术趋势明显恶化、企稳或反转；
- 价格离开原决策区间；
- 连续快速决策达到配置上限；
- 连续维持原判断达到现有定期复核上限。

第一步由综合分析模型一次性输出多头证据、空头证据、主要风险、不确定性和关键价位。第二步由决策模型结合综合报告和真实账户，输出项目现有的结构化 `Decision`。委员会直接消费 `DailyContext` 已准备的数据，不再启动分析师工具循环。

## 风控和账务边界

LLM 只提出方向、目标仓位、复核条件和关键价位。以下能力继续由确定性代码负责：

- 现金、持仓和目标仓位核对；
- 手续费、滑点和最小交易单位；
- 止损、止盈和最大回撤熔断；
- 非法或不可执行交易的拒绝/降级；
- 防未来数据和模拟日期截断。

不在自适应架构中增加独立的风险辩手节点。

## 失败处理

- 快速路径失败且已有有效观点：维持原判断，记录降级原因，次日重新评估。
- 委员会失败且已有有效观点：维持原判断，记录失败阶段，次日重新评估。
- 首日委员会失败且不存在有效观点：会话明确失败，不伪造 `hold`。
- 解析失败使用现有结构化输出修复策略，但受调用预算约束，不能无限重试。
- 经典 Graph 继续保持原有“失败即停止、不得伪装为有效 hold”的语义。

## 可观测性

每日记录和审计文本标记实际路径：`zero_call`、`fast` 或 `committee`。`llm_calls` 保存真实调用次数，`llm_calls` 明细表记录用途、模型、耗时和成功状态。会话详情展示所选架构。

## API、数据库与界面

`SessionSpec` 接受 `decision_architecture` 枚举，默认 `adaptive`。创建会话时同时写入兼容字段 `use_full_graph`。`SessionManager` 根据会话架构创建 `AdaptiveDecisionAgent`、`HybridDecisionAgent` 或 `DecisionAgent`。

Vue 新建回测页面将原复选框替换为三个单选卡片，展示调用规模和用途；正式前端与备用静态页面保持一致。会话列表或详情显示架构名称，避免用户事后无法判断结果来自哪条路径。

## 配置

新增配置项：

- `WEBAPP_ADAPTIVE_FAST_STREAK_LIMIT`：连续快速决策后强制委员会复核，默认 5。
- `WEBAPP_ADAPTIVE_MAX_CALLS_PER_DAY`：自适应路径每日直接调用上限，默认 4，为两步委员会及一次受控修复留余量。

沿用现有 `WEBAPP_MAX_STANDPAT_STREAK`、价格带和硬风控配置。

## 测试与验收

自动化测试覆盖：

- 新旧数据库迁移和旧会话模式映射；
- API 架构枚举验证与默认值；
- SessionManager 为三种模式选择正确 Agent；
- 零调用、快速和委员会路由；
- 首日委员会、重大消息、技术切换和价格越界触发；
- 快速/委员会失败降级以及首日失败；
- 调用预算和真实调用计数；
- 真实仓位核对与硬风控不回归；
- Vue 前端构建和相关 smoke 回归。

验收目标：普通无变化日为 0 次调用，一般变化不超过 1 次，委员会正常路径为 2 次；经典 Graph 和快速模式行为保持兼容。
